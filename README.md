# 流畅切换动画 · Fluid Transitions

给 SillyTavern / TauriTavern 的页面切换加上手机 App 那种进出动效。手机、电脑同一套代码。

## 管了哪些地方

| 位置 | 效果 |
| --- | --- |
| 顶栏下拉面板（API / 世界书 / 高级格式化 / 用户设置 / 背景 / 扩展 / 用户角色） | 下移 + 缩放 + 淡入，关闭反向 |
| 左右侧边栏（AI 配置栏 / 角色栏） | 从屏幕边缘滑入；手机上是整屏推入 |
| 面板互切 | 旧面板滑出与新面板滑入交叠，形成交叉过渡 |
| 弹窗 | 换掉原生的纵向压扁，改成缩放 + 上浮 + 淡入 |
| 切换聊天 / 角色 | 聊天区淡入上浮 |
| 新消息 | 单条淡入上浮（整屏重绘时不重复播放） |
| 启动 | 顶栏与聊天区依次淡入 |
| 顶栏图标 | 按下缩一下，选中的略放大 |

每一项都能单独关。风格三档：轻快（纯淡入）/ 顺滑（推入，默认）/ 弹性（带回弹）；时长 120–480ms。

## 毛玻璃（v1.5.0，读这一节）

`backdrop-filter` 的含义是「把背后的画面实时模糊一遍」。**只要对带毛玻璃的元素做 opacity 或
transform，浏览器就得把它提成合成层、并逐帧重新采样背后的画面。** 手机 WebView 上这个层
往往要等几帧才就绪，于是你会看到：先是什么都没有（面板消失），等就绪了才啪一下把毛玻璃贴上。

v1.5 的解法是**根本不去动那一层**：面板本体（毛玻璃所在的元素）从头到尾保持原样，
只让它里面的内容做动画。毛玻璃只在面板出现时算一次，既不闪，也不用逐帧重算 ——
比「换成实色底」更彻底，而且完全不碰主题的样式。

代价：面板的底瞬间就位，只有内容淡入 / 滑入。内容会被面板自己的 `overflow` 裁掉，
所以看起来是从边缘揭开，不会溢出。

| 开关 | 干什么 |
| --- | --- |
| 只让面板里的内容动 | **默认开**。带毛玻璃的面板本体不参与动画，毛玻璃不会再闪一下才出现 |
| 动画期间用同色不透明底代替毛玻璃 | 仅在上一项关掉时生效（两者互斥，勾了也不会同时作用）。动的时候实色底，停下来恢复毛玻璃 |
| 永久不要毛玻璃 | 最省。静止时也是实色底，少一点质感，但完全没有切换的瞬间 |
| 面板只淡入淡出、不位移 | 面板不动，毛玻璃采样的区域就不变，成本进一步下降 |
| 动画期间不画文字阴影 | 酒馆给所有元素都加了文字阴影，转场时省掉 |
| 关闭面板时也做动画 | **默认关**。客户端关面板时会把它移出布局，要播离场动画就得强行塞回去 —— 那是一次完整重排，手机上就是「收回卡得离谱」 |

手机首次安装（以及从 v1.4 升级）会自动设成：只让内容动、只淡入淡出、时长 140ms、
不播关闭动画、**不再替换底色**。

### 不透明底色取自你的主题

（只在「只让面板里的内容动」被你关掉时才会用到。）
颜色来源是主题变量 `--SmartThemeBlurTintColor`（客户端就是用它给面板上底色的），把透明度拉满即可。
**取不到就什么都不做**，保留原生毛玻璃 —— 绝不糊一块猜出来的颜色上去。
深色、浅色、半透明彩色主题都验过；变量损坏或完全透明时正确放弃。

底色是用 `box-shadow: inset` 铺的，不是改 `background-color`：有些主题用 ID 选择器 +
`!important` 写死了面板底色，权重压过插件，于是会出现「模糊被关掉了、底色却还是半透明」，
背后的聊天文字就透上来了。inset 阴影画在「背景之上、内容之下」，不跟主题争同一个属性。

### 诊断读数

手机上开不了控制台，所以设置面板底部有一行读数：打开出问题的那个面板，回来点「刷新读数」，
把那行字发给作者即可定位。关键字段：`bgA` 面板底色的不透明度（关掉毛玻璃后若小于 1，
就是主题的规则压过了插件）、`blur` 毛玻璃当前是否生效、`mid=p0/k1` 动画进行中面板本体
应当有 0 个动画、子节点 1 个（这就是「只让内容动」是否真的生效）。

### 顶栏面板打开时那一下卡顿不是动画造成的

「用户设置」「高级格式化」这类面板里塞着几百个控件，从隐藏变成显示时浏览器要真刀真枪排一次版，
这笔钱原生酒馆也付，只是它不做动画，你看到的就是「卡一下然后出现」。
如果这段排版比动画时长还久，动画会在你看到画面之前就播完 —— 表现就是「卡一会直接出页面，没有动画」。
**这部分插件删不掉。** 手机上如果嫌卡，把「顶栏下拉面板」这一项关掉是完全合理的选择。

### v1.2.0 那套「提速」已整体删除

`keepWarm`（关着的面板保持就绪）、提前加载头像、跳过 125ms 等待、掉帧自动降级 —— 全部移除。
它们针对的是「打开面板要重排几百张角色卡」，而真机上的瓶颈是绘制，不是排版。
在手机上净收益为负，还引入了三个真实故障：顶栏下方一片毛玻璃雾（关着的面板没能真正折叠）、
点一下闪一帧、以及快速切换时越切越卡。

同时修掉两个从 v1.1.0 就存在的 bug：

- **点一下闪一帧**：进场动画的第一帧要等动画真正开跑才生效，于是有一帧是「面板已按最终样子画出来」。
  桌面上看不见，手机上一帧就是三五十毫秒。已改为 `fill: both`。
- **快速切换越切越卡**：动画被打断时原先用 `getComputedStyle()` 取当前位置再重建动画，
  而读计算样式会强制浏览器立刻重算整个文档的样式和布局。现在改成让原动画反向播（`reverse()`），
  不读任何东西。实测同样 15 次快速切换：**旧版触发 14 次强制重排，新版 0 次**。

## 安装

**方式 A：手动**
把 `manifest.json` / `index.js` / `style.css` 放进酒馆数据目录的
`extensions/fluid-transitions/`，重启客户端。

**方式 B：Git URL（推荐）**
在酒馆「扩展 → 安装扩展」里填 `https://github.com/tqzbceb/animation`。
更新也点同一处重装即可。

装好后设置在「扩展」面板里，标题是「流畅切换动画」。

## 设计约定

- 动画本体用 Web Animations API，不依赖 `calc-size()` / `@starting-style`，老 WebView 也能跑。
- 不改任何 DOM 结构，只加 class 和动画；关掉开关后原生的过渡属性逐字还原。
- 勾了酒馆的「减少动画」或系统开启了 prefers-reduced-motion 时自动让位给原生行为（可关）。
- 侧边栏横滑期间会临时给 `<html>` 加 `overflow: hidden`，避免手机上闪一条横向滚动条。
- 低端手机可以打开「动画期间关闭毛玻璃」换帧率。
- 不透明底色算不出来时（拿不到主题色）会自动退回原生毛玻璃，不会出现透字。
- 动画被打断一律用反向播，全程不读计算样式，所以快速连点不会引发重排风暴。

## 调试

控制台里有 `fluidTransitions`：

```js
fluidTransitions.cfg()            // 取当前设置对象，改完调 apply()
fluidTransitions.apply()          // 让改动生效
fluidTransitions.preview()        // 重播一次面板动画
fluidTransitions.launch()         // 重播启动动画
fluidTransitions.teardown()       // 完全卸下，回到原生行为
fluidTransitions.solid()          // 看算出来的不透明底色
fluidTransitions.recolor()        // 换主题后重算底色
```

在 TauriTavern v1.6.5（SillyTavern 1.16 系）上开发并测试。
